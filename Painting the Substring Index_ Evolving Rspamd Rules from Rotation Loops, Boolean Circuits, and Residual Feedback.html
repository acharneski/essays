1. The Problem

Rspamd configurations are usually written by hand. An operator sees a campaign, writes a regular expression, gives it a symbol name and a score, and maybe combines it with other symbols in a composite. Over time the configuration accumulates hundreds of these symbols. Each one was locally reasonable when it was written. Together they are poorly understood: scores were guessed, overlaps are unknown, and some expressions match nothing. Meanwhile new spam sails past.

This essay describes a way to derive that configuration from labelled mail rather than write it by hand. The approach has three parts that feed one another:

  1. Phase 1, substring discovery. All messages go into one combinatorial text index. Each message is an independent cyclic “loop”. Labels (spam, ham, phishing, a campaign topic) are painted onto the index. Substrings whose painted mass is strongly skewed toward a tag become candidate regexp symbols.
  2. Phase 2, circuit compression. The candidate symbols, together with Rspamd's existing symbols, are the inputs to a genetically optimised Boolean circuit. The circuit maps directly onto Rspamd composites. Its scored output is a baseline predictor.
  3. Phase 3, residual feedback. The baseline's errors are painted back onto the same index, replacing the raw labels. Substrings that explain what the baseline gets wrong become the next generation of candidates.

The loop then repeats. The result is a rule-based fuzzy ensemble that you can read line by line, that emits native Rspamd configuration, and that grows only where the existing rules fail.

The rest of the essay covers the theory and the algorithms. Operational detail is included only where it constrains the design.

2. Why a Rotation Index Fits the Problem

2.1 Rspamd's scoring model

Rspamd is an additive scorer. For a message m, each symbol k either fires or does not. Its score sk is added to a total:

S(m) = ∑k sk · 𝟏[symbol k fires on m]

The total is compared against action thresholds (greylist, add header, rewrite subject, reject). Two refinements matter here:

  • Composites are Boolean expressions over other symbols, such as A & !B | C. They define a new symbol with its own score. By default they can also remove the scores of their constituent symbols.
  • Regexp and multimap rules match content. They run through Hyperscan, so a few hundred literal or near-literal patterns cost almost nothing at scan time.

So Rspamd already is a fuzzy ensemble. Atomic detectors produce Boolean evidence, composites form logical combinations, and a weighted sum produces a graded verdict. What is missing is a principled way to choose the detectors, the combinations and the weights. The three phases fill those three gaps in order.

2.2 Messages as independent loops

Let the corpus be messages T1, …, TM. Each message is normalised into a string (Section 7 covers the normalisation steps). Each message is treated as a cyclic string, or loop: its rotations are all of its cyclic shifts.

The structure that holds many loops in one sorted index is the extended Burrows–Wheeler Transform (eBWT). It sorts the rotations of every string together, using ω-order (comparison of infinite periodic repetitions). The ordinary BWT matrix of a single text has one row per rotation of that text. The eBWT matrix has one row per rotation of every message, interleaved in one lexicographic order.

In practice it is often simpler to build a generalised suffix array over the concatenation T1$1T2$2···TM$M, using unique separators. The separators make sure no substring crosses a message boundary. Both constructions give the property we need:

All occurrences of a substring s, across all messages, occupy one contiguous interval of rows in the sorted matrix.

This is the substring index. Each interval is a node of the implicit suffix tree, an LCP interval [l, r] with depth d. It stands for the substring s of length d shared by rows l..r. Rows next to each other share long prefixes, so the sorted order groups together the places where the same textual context appears. That is the clustering an embedding would give you, but here it is exact, invertible and needs no training.

Treating messages as loops rather than plain strings is a deliberate choice. A message is a bag of contexts, not a sequence with a privileged beginning. The cyclic view treats the text as rotation-invariant at the document level while keeping exact local order inside each context.

2.3 Tags attach to loops, influence attaches to intervals

Tags live on messages. Each loop Tm carries a label vector ym, for example ymspam ∈ {0,1}, or a topic tag such as crypto_scam or invoice_phish. Every row (rotation) of the matrix knows which loop it came from. This is the document array DA[i], an inexpensive by-product of construction.

Painting an indicator on the substring index means computing, for every LCP interval, an aggregate of the tags of the loops whose rotations fall inside it. A tag is a property of a whole message. Painting turns it into a field over substrings: the field is high where a substring's contexts belong to tagged messages and low where they do not.

3. Phase 1: Painting and Substring Discovery

3.1 Distinct-document counts

The naive count, the number of rows in an interval, rewards substrings that repeat inside one message. A spam message containing “unsubscribe” forty times would dominate. Messages are the unit of evidence, so we count distinct documents per interval:

n(s) = |{DA[i] : i ∈ [l,r]}|,  nt(s) = |{DA[i] : i ∈ [l,r], yDA[i]t = 1}|

Distinct colours can be counted for every suffix-tree node in linear time with the standard technique. For each row, find the previous row from the same document. Add +1 at the row and −1 at the lowest common ancestor of the two rows. The count for a node is then the sum over its subtree. Doing this once per tag (or with a weighted variant, Section 3.4) gives every interval its painted counts in O(N) total, where N is the corpus length.

3.2 From counts to a fuzzy membership

Raw ratios are unstable at low support. We use a Beta-smoothed log-odds relative to the prior:

λt(s) = log [ (nt(s) + απt) / (n(s) − nt(s) + α(1−πt)) ] − log [ πt / (1−πt) ]

Here πt is the base rate of tag t and α is the prior strength. The fuzzy membership of substring s in tag t is

μt(s) = σ(λt(s))

Its value is 0.5 for an uninformative substring. It approaches 1 for a substring that is strongly indicative and approaches 0 for one that is strongly counter-indicative.

Ranking candidates by λ alone still favours tiny counts that happen to be perfectly skewed. We therefore rank by a lower confidence bound on the tag rate: the Wilson lower bound of nt/n for positive indicators, and the upper bound for negative ones. This is the conservative “how sure are we this substring is spammy” question an operator would ask.

3.3 Selecting informative intervals: branch-point selection

There are O(N) LCP intervals, which is far too many to turn into rules, and most of them are redundant. If “bitcoin wallet” is painted strongly, then “bitcoin walle” is painted almost identically.

We use the tree structure. A child interval (a longer substring) is worth keeping only if its painting differs significantly from its parent's. The test is the information gain of the split, measured as the KL divergence between the child's smoothed tag distribution and the parent's, weighted by the child's support:

Δ(s) = n(s) · DKL( p̂t(s) ‖ p̂t(parent(s)) )

A candidate is emitted when four conditions hold:

  • n(s) ≥ nmin (minimum document support),
  • |s| ≥ Lmin (avoids short, overly generic patterns),
  • the confidence bound on its tag rate exceeds a threshold,
  • Δ(s) is maximal along its root-to-leaf path, or it is the right-maximal boundary at which the painting stabilises.

This is the substring version of choosing a split in a decision tree. The extension stops at the point where adding characters no longer changes what the substring says about the tag. These branch points are the natural boundaries of a rule. They are also usually the substrings a human analyst would have picked.

A post-pass removes subsumed candidates. If s1 is a substring of s2 and both cover nearly the same documents, keep only the one with the better confidence bound.

3.4 Weighted painting, negative increments, and contradiction

The painting operator generalises beyond binary tags. Give each message a real weight wm and paint

P(s) = ∑m ∈ D(s) wm

where D(s) is the set of distinct documents in the interval. A few cases follow:

  • wm = ym − π recovers a centred version of the tag count.
  • wm < 0 for ham means a substring common in legitimate mail is painted down. This is the “negative increment” or contradiction mechanism. A substring can only earn a positive spam score if its spam mass outweighs its ham mass.
  • Phase 3 replaces wm with residuals, which turns the same machinery into the feedback engine (Section 5).

Several tags can be painted at once as a vector field. Topic tags (for example pharma, sextortion, invoice_phish) produce per-topic candidate sets. Each set becomes a symbol group in Rspamd.

3.5 From interval to rule

Each surviving interval becomes an atomic detector. In its simplest form that is an escaped literal over the normalised text, compiled into a regexp symbol. Two generalisations are worth having:

  • Gapped pairs. Two candidates that frequently co-occur in the same messages within a short distance can be merged into A.{0,k}B. Co-occurrence is cheap to measure from the document array.
  • Character-class lifting. Candidates that differ only in digits, or that share a homoglyph equivalence class after normalisation, can be merged into one pattern with a class.

Each lifted pattern must be re-scored against the corpus. Generalisation always raises recall and can damage precision, so the confidence bound has to be recomputed on the actual match set.

At the end of Phase 1 the system has a pool of K candidate atoms x1, …, xK. Each atom is a Boolean function over messages with a painted membership value attached.

4. Phase 2: Compressing the Rule Pool into a Boolean Circuit

4.1 Why a circuit

One could simply give every atom a score proportional to λ and add them up, which amounts to a naive Bayes over substrings. This fails in two predictable ways:

  1. Correlated evidence is double-counted. Twelve substrings from the same campaign template all fire together and push a borderline message far past reject.
  2. Context-dependent evidence is lost. “Wire transfer” is meaningful in mail from an unknown sender with failed DMARC, and harmless from an authenticated finance partner. An additive model cannot express “only when”.

A Boolean circuit over the atoms and over existing Rspamd symbols (R_SPF_FAIL, DMARC_POLICY_REJECT, FREEMAIL_FROM, MIME_HTML_ONLY, BAYES_SPAM, and so on) addresses both problems. AND gates express conjunctions of context. OR gates collapse correlated atoms into one unit of evidence. NOT gates express exceptions. Rspamd composites are exactly this kind of circuit, so the optimised result can be deployed with no runtime cost beyond what Rspamd already does.

4.2 Binary atoms

The fuzzy memberships from Phase 1 are attached to the atoms, but Rspamd composites are Boolean. Each atom is therefore used as a crisp input: it either matched the message or it did not. The fuzziness does not disappear. It moves into two places:

  • the score attached to each circuit output, fitted in Section 4.6, and
  • the seeding and mutation priors of the genetic search, which favour atoms with high |λ|.

A hybrid alternative uses Łukasiewicz gates (a ∧ b = max(0, a+b−1), a ∨ b = min(1, a+b)) on graded memberships. It is useful for offline analysis, but it cannot be expressed in Rspamd composites. The deployable path is to threshold first and then evolve.

4.3 Representation: Cartesian Genetic Programming

Circuits are encoded with Cartesian Genetic Programming (CGP). A genome is a fixed-length array of G nodes. Each node is a triple (op, in1, in2) with op ∈ {AND, OR, ANDNOT, XOR, NOT}. Its inputs refer either to atoms or to earlier nodes, so the circuit is acyclic by construction. One or more output genes select which nodes are emitted as composite symbols.

CGP suits this problem for three reasons:

  • Neutral drift. Inactive nodes carry hidden genetic material that can become active after a single mutation. This helps the search escape plateaus.
  • Bounded size. G is a hard upper bound on circuit size, which keeps the output readable.
  • Multiple outputs. One genome can define several composites that share subexpressions. This mirrors how a hand-written config reuses intermediate composites.

XOR has no native operator in Rspamd composites. It is expanded during emission into (a & !b) | (!a & b), and the complexity penalty charges it accordingly.

4.4 Bit-parallel evaluation

Fitness evaluation dominates the run time, and it has a convenient structure. Every atom is evaluated once on every message, producing a bitset of length M. A circuit is then evaluated on the whole corpus with word-wide bitwise operations:

for node in active_nodes(genome):          # topological order
    a = value[node.in1]; b = value[node.in2]
    value[node] = a & b      if op == AND
                  a | b      if op == OR
                  a & ~b     if op == ANDNOT
                  a ^ b      if op == XOR
                  ~a         if op == NOT
fires = value[output]                      # bitset over messages
TP = popcount(fires & SPAM); FP = popcount(fires & HAM)

The cost is O(|active| · M / 64) per genome. With M = 106 messages and fifty active gates, one genome takes under a millisecond. A population of hundreds can therefore run for thousands of generations on a single machine.

4.5 Fitness: asymmetric cost plus description length

Mail filtering is asymmetric. A false positive (legitimate mail rejected) costs far more than a false negative. The fitness to minimise is

J(C) = cFP·FP(C) + cFN·FN(C) + λg|C|gates + λddepth(C) + λa|atoms(C)|

with cFP ≫ cFN; a ratio of 10–100 is typical. The structural terms are a minimum-description-length penalty. A gate must pay for itself in errors removed, which is what keeps the circuit compact enough to read. Penalising distinct atoms also discourages the circuit from depending on many fragile substrings when a few robust ones would do.

Because the trade-off between FP, FN and size is a policy decision rather than a fixed constant, it is better to run a multi-objective search (NSGA-II style) over (FP, FN, size). That produces a Pareto front, and the operator picks the point that matches local tolerance. A small circuit with very low FP can ship to reject. A larger circuit with higher recall can ship to add header.

4.6 Fitting scores to the circuit

The circuit chooses the structure. Scores have to be fitted separately, because the final verdict is still Rspamd's additive sum compared against thresholds.

Given the outputs o1, …, oJ of the evolved composites (and, optionally, the atoms left as standalone symbols), fit scores sj by cost-sensitive logistic regression on the margin S(m) − θ, where θ is the target action threshold. A box constraint keeps every individual score inside an operator-approved range, so that no single new symbol can reject mail on its own unless that is intended.

If the circuit is meant to sit next to an existing, trusted config, the fit is done against the residual of the existing score. In that case the new symbols only add what the existing rules are missing.

4.7 Seeding and search dynamics

A random initial population wastes many generations rediscovering obvious single-atom rules. A better starting population includes:

  • the top single atoms by confidence bound, as trivial one-gate circuits;
  • the top pairs by conditional lift P(spam | a ∧ b) / P(spam | a);
  • the operator's existing composites, translated into genomes.

Including existing composites means the search starts from current production behaviour and can only be selected toward improvements that pay their complexity cost.

Mutation is point mutation over node genes. Input mutation is biased toward atoms with high |λ|, and op mutation is uniform. Plain CGP does not use crossover. A subgraph-splice crossover is worth adding when several outputs are evolved together, because it lets a useful sub-circuit move between output composites.

5. Phase 3: The Baseline Repaints the Index

5.1 Baseline prediction

After Phase 2 there is a scored configuration: atoms, composites and scores. For each training message it produces a total score and a probability

p̂m = σ(S(m) − θ)

This is the baseline prediction. It is the best the current rule set can do.

5.2 Residual painting

Now go back to the index and repaint it. This time the weight is not the raw label but the residual, which is the negative gradient of the log-loss:

wm = ym − p̂m

and the same painting operator from Section 3.4 is applied:

R(s) = ∑m ∈ D(s) wm

The residual field has a precise reading:

  • R(s) ≫ 0: the substring appears in spam the baseline under-scores. It is a missing positive indicator.
  • R(s) ≪ 0: the substring appears in ham the baseline over-scores. It is a missing negative indicator. It should become a negative-score symbol or, more likely, a NOT input to an existing composite (an exception clause).
  • R(s) ≈ 0, even when the raw painting λ(s) is large: the substring is already explained. It is redundant and should not be added again.

The last point matters most. A naive system rediscovers the same campaign strings every cycle. Residual painting makes already-captured evidence invisible, so discovery concentrates on what the configuration currently fails to explain.

Mathematically this is gradient boosting. Its weak learners are substring indicators chosen by linear-time interval enumeration, and its consolidation step is the circuit compression of Phase 2 rather than additive stacking. The selection machinery of Section 3.3 (support, confidence bound, branch-point selection) is reused unchanged on the residual field. Confidence bounds on a real-valued sum use a bootstrap or a normal approximation over the wm in the interval.

5.3 The full loop

config  ← existing rspamd config (possibly empty)
index   ← build_eBWT_or_GSA(normalised corpus)
loop:
    p̂      ← evaluate(config, corpus)                # baseline
    w      ← y − p̂                                   # residuals (or y − π on first pass)
    field  ← paint(index, w)                          # distinct-doc weighted sums per interval
    cands  ← select_branch_points(field, n_min, L_min, conf)
    cands  ← dedupe_subsumed(cands) ∪ lift_generalisations(cands)
    atoms  ← atoms ∪ cands
    bits   ← evaluate_bitsets(atoms ∪ native_symbols, corpus)
    front  ← NSGA_CGP(bits, labels, seed=config.composites)
    C*     ← pick(front, policy)                      # operator FP tolerance
    scores ← fit_scores(C*, residual_of=trusted_base)
    if validation_gain(config ⊕ (C*, scores)) < ε: break
    config ← config ⊕ (C*, scores)
    atoms  ← prune(atoms, keep = atoms used by config)
emit(config)

5.4 Convergence and stopping

Each cycle can only add rules that reduce held-out cost after the complexity penalty. Validation cost is therefore non-increasing when measured on a fixed split, and the loop stops when the marginal gain drops below ε.

In practice it settles after a few cycles. The first cycle captures broad campaign vocabulary. The second captures exceptions (ham that used that vocabulary) and context conjunctions. Later cycles find narrow, low-support patterns, and the confidence bounds filter most of those out.

The pruning step matters. Atoms that the final circuit does not use are dropped, so the atom pool stays bounded and the next Phase 2 search space does not grow without limit.

6. Why the Pieces Fit

It is worth stating why these three components belong together rather than just being stacked.

  • The index supplies hypotheses. Every possible substring rule corresponds to an interval, and all intervals can be enumerated and painted in linear time. Discovery is exhaustive over contiguous patterns, not sampled.
  • Painting is the shared language. Labels, residuals and contradiction weights are all just wm. One operator, P(s) = ∑m ∈ D(s) wm, serves first-pass discovery, error-driven discovery and negative evidence.
  • The circuit is the compression step. The index can produce thousands of correlated candidates. The circuit forces them through a description-length bottleneck and returns a handful of logical structures. Those structures match Rspamd's composite semantics exactly.
  • The baseline closes the loop. Feeding residuals back means each phase measures the other. The circuit tells the index what is already known, and the index tells the circuit what it is missing.

The result is a learned model whose every parameter is a readable artefact: a literal pattern, a composite expression, a score. It does not depend on embeddings, a neural runtime, or a model file whose decisions cannot be inspected.

7. Constraints from the Mail Domain

The theory above is general. The mail domain imposes a few requirements that shape the algorithm.

  • Normalisation is part of the model. The index is built over a canonical form of each message: MIME-decoded, HTML stripped to visible text, Unicode NFKC-normalised, case-folded, homoglyphs and zero-width characters collapsed, whitespace runs reduced, and URLs replaced by their registrable domain plus a path token. Emitted regexps must target the same canonical form, either through Rspamd's normalised text parts or a Lua pre-filter. If the index and the runtime see different text, the painted statistics do not hold.
  • Separators matter. Subject, body text, URL list and selected headers can be indexed as separate loops of the same message. They share a document id but have distinct field markers. Candidates are then field-scoped, which matches how Rspamd regexps are scoped (Subject=/.../, /.../{mime}, /.../{url}).
  • Time-split validation. Spam campaigns are bursty. A random train/validation split leaks campaign templates and overstates precision. Validation must be strictly later in time than training, and the support threshold nmin should count distinct senders or campaign clusters rather than raw messages, so that one blast cannot create a rule by itself.
  • Adversarial decay. Substring rules lose their value as spammers adapt. Each emitted symbol carries its creation time and its painted statistics. A periodic re-paint on recent traffic measures its live λ. Symbols whose confidence bound falls below threshold are retired automatically, and the circuit is re-evolved without them.
  • Shadow deployment. New symbols first ship with score 0. They log, but they do not act. Their production firing rates are compared against the offline predictions, and only symbols that agree are promoted to their fitted scores. The verdict logs from this period are also a natural source of new training labels, especially for ham, through user “not spam” actions.
  • Scale. A compressed FM-index over a few million normalised messages fits in memory on one machine. Construction (SA-IS plus Kasai LCP), interval enumeration and distinct-document painting are all linear. Circuit evolution is bit-parallel. A full cycle is a nightly batch job, not a cluster workload.

8. Emitting Configuration

The output maps directly onto standard Rspamd local overrides.

Atoms become regexp symbols:

-- local.d/regexp/auto_substr.lua  (generated)
config['regexp']['AUTO_S_7f3a'] = {
  re = '/claim\\s+your\\s+wallet\\s+bonus/i{mime}',
  score = 0.0,                       -- used only via composites
  description = 'auto: λ=4.1 n=812 cycle=2',
  group = 'auto_substr',
}

Circuit outputs become composites. Shared subexpressions are emitted as intermediate composites, and XOR is expanded:

# local.d/composites.conf  (generated)
AUTO_C_CRYPTO_LURE {
  expression = "(AUTO_S_7f3a | AUTO_S_91bc) & !R_DKIM_ALLOW & (FREEMAIL_FROM | R_SPF_SOFTFAIL)";
  score = 6.2;
  group = "auto_composite";
  policy = "remove_weight";
}
AUTO_C_INVOICE_EXCEPT {
  expression = "AUTO_S_44e0 & !AUTO_S_b812";
  score = 3.1;
  group = "auto_composite";
}

Atoms that survive as standalone evidence get their fitted scores directly. Every generated rule carries its painted statistics in the description, so an operator reviewing a verdict can see why each symbol exists.

9. Summary

The idea starts from one observation: in a sorted rotation index, every substring is a contiguous interval, and every interval can carry the tags of the loops that pass through it. Painting labels onto that index gives exhaustive, linear-time discovery of substring rules. Compressing the discovered rules into a genetically optimised Boolean circuit removes redundancy and adds context, and the circuit is already in the form of Rspamd composites. Repainting the index with the circuit's residuals turns discovery into a gradient-boosting loop that only looks for what the current configuration misses.

The end product is an Rspamd configuration that is generated, validated and retired by algorithm, yet stays fully readable: literal patterns, Boolean composites and scores, each with the statistics that justified it.
